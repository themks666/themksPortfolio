# Expert Systems and Learning in Machines

Artificial Intelligence is concerned with building systems that can perform tasks that normally require human intelligence, such as learning, reasoning, decision-making, problem-solving, perception, and understanding language.

One important area of Artificial Intelligence is the **expert system**. An expert system attempts to solve problems in a particular domain by using knowledge and reasoning techniques similar to those of a human expert.

Expert systems became an important part of early Artificial Intelligence research and introduced many concepts that are still relevant today, including:

* Knowledge representation
* Knowledge acquisition
* Rule-based reasoning
* Inference
* Problem solving
* Decision support
* Explanation and justification

At the same time, the development of machine learning introduced another way for machines to acquire knowledge: instead of explicitly encoding every rule, a machine can learn patterns from examples and data.

This article covers the major concepts required to understand **learning in machines and expert systems**, including their architecture, knowledge types, knowledge acquisition, knowledge elicitation, inference methods, and the development process.

---

# 1. Introduction to Learning in Machines

## 1.1 What Is Learning?

Learning is the process through which a system improves its ability to perform a task using experience, examples, observations, or feedback.

In humans, learning can occur through:

* Experience
* Observation
* Practice
* Instruction
* Feedback
* Experimentation

A machine can also learn from information provided to it.

The general idea can be represented as:

```text
Experience / Data
       |
       v
 Learning Process
       |
       v
Knowledge or Model
       |
       v
Improved Performance
```

For example, if a computer is shown many examples of spam and non-spam emails, it can learn patterns that help classify future emails.

---

## 1.2 Learning in Machines

Machine learning is a branch of Artificial Intelligence in which computer systems learn patterns from data and use those patterns to make predictions or decisions.

Traditional programming generally follows:

```text
Input + Program
      |
      v
    Output
```

Machine learning commonly follows:

```text
Data + Examples
      |
      v
Learning Algorithm
      |
      v
Trained Model
      |
      v
New Input
      |
      v
Prediction / Decision
```

For example, consider a system that predicts house prices.

The training data may contain:

```text
House Size
Number of Rooms
Location
Age
Price
```

The machine learning algorithm finds relationships among these variables and learns a model that can estimate the price of a new house.

---

## 1.3 Why Is Machine Learning Important?

The amount of digital information generated every day is enormous. It is often difficult to write explicit rules for every possible situation.

Machine learning is useful when:

* There are large amounts of data
* Patterns are difficult to describe manually
* The problem changes over time
* Predictions are required
* Complex relationships exist between variables
* A system needs to improve using experience

For example, writing rules for every possible form of handwritten digit would be extremely difficult.

Instead, a machine learning system can learn from thousands of examples.

---

# 1.4 Types of Learning in Machines

Machine learning is commonly divided into several categories.

## Supervised Learning

In supervised learning, the system learns from labeled examples.

```text
Input + Correct Output
          |
          v
      Algorithm
          |
          v
      Trained Model
```

For example:

```text
Email -> Spam
Email -> Not Spam
Email -> Spam
Email -> Not Spam
```

The machine learns the relationship between input and expected output.

Common supervised learning tasks include:

* Classification
* Regression

Examples:

```text
Classification:
Disease or No Disease

Regression:
Predicting House Price
```

---

## Unsupervised Learning

In unsupervised learning, the system receives data without predefined labels and attempts to discover useful patterns.

```text
Unlabeled Data
      |
      v
Learning Algorithm
      |
      v
Discovered Patterns
```

Examples include:

* Clustering
* Dimensionality reduction
* Association analysis

For example, a business may provide customer purchasing data and ask an algorithm to identify groups of customers with similar behavior.

---

## Reinforcement Learning

In reinforcement learning, an agent learns by interacting with an environment.

The agent receives rewards or penalties based on its actions.

```text
          +----------------+
          |  Environment   |
          +-------+--------+
                  |
                  v
                State
                  |
                  v
                Agent
                  |
                  v
               Action
                  |
                  v
             Reward/Penalty
```

The objective is to learn actions that maximize long-term reward.

Examples include:

* Game playing
* Robotics
* Autonomous control
* Resource management

---

# 1.5 Machine Learning and Expert Systems

Machine learning and expert systems are both parts of Artificial Intelligence, but they generally acquire knowledge in different ways.

An expert system traditionally depends on knowledge explicitly represented by experts.

```text
Human Expert
     |
     v
Knowledge Acquisition
     |
     v
Knowledge Base
     |
     v
Inference Engine
```

A machine learning system generally learns from data.

```text
Training Data
     |
     v
Learning Algorithm
     |
     v
Machine Learning Model
```

Therefore:

```text
Expert System
    -> Knowledge is explicitly represented

Machine Learning
    -> Patterns are learned from data
```

Modern AI systems can also combine these approaches.

# 2. Architecture of an Expert System

## 2.1 What Is an Expert System?

An expert system is an AI system designed to solve problems in a specific domain using stored knowledge and reasoning techniques.

It generally attempts to provide answers, recommendations, diagnoses, or decisions similar to those produced by a human expert.

Examples of domains include:

* Medical diagnosis
* Banking
* Agriculture
* Manufacturing
* Equipment troubleshooting
* Finance
* Customer support
* Education
* Legal decision support

---

# 2.2 Basic Architecture

A typical expert system consists of several major components.

```text
                 +------------------+
                 |       User       |
                 +--------+---------+
                          |
                          v
                 +------------------+
                 | User Interface   |
                 +--------+---------+
                          |
                          v
                 +------------------+
                 | Inference Engine |
                 +----+--------+----+
                      |        |
                      v        v
              +-----------+ +-----------+
              | Knowledge | |  Working  |
              |   Base    | |  Memory   |
              +-----------+ +-----------+
                      |
                      v
              +---------------+
              | Explanation   |
              |    Facility   |
              +---------------+
```

The major components are:

1. Knowledge Base
2. Inference Engine
3. Working Memory
4. User Interface
5. Explanation Facility
6. Knowledge Acquisition Facility

---

# 2.3 Knowledge Base

The **knowledge base** contains the domain knowledge used by the expert system.

It may contain:

* Facts
* Rules
* Relationships
* Heuristics
* Procedures
* Domain concepts

For example:

```text
Fact:
The patient has a fever.

Fact:
The patient has a cough.
```

A rule may be:

```text
IF fever AND cough
THEN possible respiratory infection
```

The knowledge base therefore acts as the main source of domain-specific knowledge.

---

# 2.4 Inference Engine

The **inference engine** is the reasoning component of an expert system.

It uses the knowledge contained in the knowledge base and applies rules to the current facts.

For example:

```text
Fact:
Temperature is high.

Rule:
IF temperature is high
THEN fever is present.
```

The inference engine applies the rule and derives:

```text
Fever is present.
```

The inference engine may use techniques such as:

* Forward chaining
* Backward chaining

---

# 2.5 Working Memory

Working memory stores information about the current problem.

It may contain:

* User inputs
* Observed facts
* Intermediate conclusions
* Temporary results

For example:

```text
Working Memory

Patient has:
- Fever
- Cough
- Headache
```

The inference engine uses these facts while solving the problem.

---

# 2.6 User Interface

The user interface allows users to communicate with the expert system.

The user may:

* Enter information
* Answer questions
* Request a diagnosis
* View recommendations
* Examine explanations

A simple interaction could look like:

```text
System:
Do you have a fever?

User:
Yes

System:
Do you have a cough?

User:
Yes

System:
Possible respiratory infection.
```

---

# 2.7 Explanation Facility

One important characteristic of an expert system is the ability to explain how it reached a conclusion.

For example:

```text
Conclusion:
Possible respiratory infection.

Reason:
Fever = Yes
Cough = Yes
Difficulty breathing = Yes

Rule applied:
IF fever AND cough AND breathing difficulty
THEN respiratory infection is possible.
```

The explanation facility is useful because users may want to understand not only the answer but also the reasoning behind it.

---

# 2.8 Knowledge Acquisition Facility

The knowledge acquisition facility is used to collect, organize, update, and maintain knowledge for the expert system.

Knowledge may come from:

* Human experts
* Books
* Manuals
* Databases
* Research papers
* Existing systems
* Historical records

This process is discussed in more detail in the Knowledge Acquisition section.

---

# 2.9 Characteristics of an Expert System

Expert systems have several important characteristics.

## Domain Specific

An expert system usually focuses on a specific problem domain.

For example:

```text
Medical Expert System
```

would specialize in medical diagnosis rather than every possible type of problem.

---

## Knowledge Based

Its decisions depend on stored domain knowledge.

```text
Knowledge
    +
Reasoning
    =
Decision
```

---

## Reasoning Ability

The system can apply rules to known facts in order to derive new conclusions.

---

## Consistent Performance

A properly designed system can apply the same rules consistently.

A human expert may make different decisions depending on circumstances, workload, or available information. A rule-based system generally follows its encoded reasoning process consistently.

---

## Explanation Capability

An expert system may explain why a particular conclusion was produced.

---

## Limited Domain

Traditional expert systems usually do not possess general human intelligence.

For example, a medical expert system may diagnose diseases but cannot automatically perform unrelated tasks such as writing software or controlling a factory robot unless those capabilities are specifically designed.

---

## Availability

A computer-based system can potentially be made available continuously.

---

## Knowledge Maintenance

The knowledge base can be updated when new knowledge becomes available.

---

# 2.10 Advantages of Expert Systems

Expert systems can provide several benefits:

### Availability

They can provide assistance without requiring a human expert to be available at every moment.

### Consistency

Rules can be applied consistently.

### Knowledge Preservation

Expert knowledge can be documented and stored in the system.

### Decision Support

The system can assist users in analyzing complex situations.

### Reduced Response Time

A computer can process a large number of rules quickly.

### Training Support

Expert systems can also be used as educational tools to demonstrate expert reasoning.

---

# 2.11 Limitations of Expert Systems

Traditional expert systems also have limitations.

### Knowledge Acquisition Problem

Obtaining expert knowledge can be difficult and time-consuming.

### Limited Common Sense

A rule-based system may not possess the broad common-sense understanding of a human.

### Domain Dependence

A system built for one domain generally cannot automatically solve unrelated problems.

### Maintenance

Large knowledge bases can become difficult to maintain.

### Dependence on Knowledge Quality

If the knowledge base contains inaccurate, incomplete, or outdated information, the system's conclusions can also be unreliable.

# 3. Categories of Knowledge

Knowledge is the central component of an expert system.

Different kinds of knowledge are used to represent different aspects of a problem.

The major categories include:

```text
Knowledge
   |
   +-- Declarative Knowledge
   |
   +-- Procedural Knowledge
   |
   +-- Heuristic Knowledge
   |
   +-- Meta Knowledge
   |
   +-- Structural Knowledge
   |
   +-- Common-Sense Knowledge
```

---

# 3.1 Declarative Knowledge

Declarative knowledge describes **what is true**.

It consists of facts and statements about objects, events, and relationships.

Example:

```text
Nepal is a country.

A dog is an animal.

John is an employee.

Temperature is 40°C.
```

In an expert system:

```text
Fact:
Patient has fever.
```

Declarative knowledge answers:

> What is known?

---

# 3.2 Procedural Knowledge

Procedural knowledge describes **how something is done**.

It represents procedures, methods, and steps.

For example:

```text
To diagnose the problem:

1. Check the symptoms.
2. Check the test results.
3. Compare the symptoms with known conditions.
4. Produce a possible diagnosis.
```

Procedural knowledge answers:

> How should the task be performed?

---

# 3.3 Heuristic Knowledge

Heuristic knowledge represents rules of thumb derived from experience.

It is especially important in expert systems because human experts often solve problems using experience-based strategies.

Example:

```text
IF the engine makes a clicking sound
AND the battery is weak
THEN check the battery connections first.
```

A heuristic does not necessarily guarantee a mathematically optimal answer. It provides a useful strategy based on experience.

---

# 3.4 Meta Knowledge

Meta knowledge is **knowledge about knowledge**.

It can describe:

* Which rule should be applied first
* Which source is more reliable
* Which reasoning strategy should be used
* How knowledge should be organized

For example:

```text
If two rules can be applied,
prefer the rule with higher priority.
```

This information helps control the reasoning process.

---

# 3.5 Structural Knowledge

Structural knowledge describes relationships among concepts.

For example:

```text
Car
 |
 +-- Engine
 |
 +-- Wheels
 |
 +-- Transmission
```

Or:

```text
Animal
   |
   +-- Mammal
   |      |
   |      +-- Dog
   |
   +-- Bird
          |
          +-- Eagle
```

Structural knowledge helps the system understand how concepts are related.

---

# 3.6 Common-Sense Knowledge

Common-sense knowledge represents general knowledge about the world.

Examples:

```text
Water is generally wet.

People need food to survive.

Objects can fall downward because of gravity.
```

Human beings naturally possess a large amount of common-sense knowledge.

Representing all common-sense knowledge in a traditional expert system can be extremely difficult.

---

# 3.7 Explicit and Tacit Knowledge

Knowledge can also be divided into explicit and tacit forms.

## Explicit Knowledge

Knowledge that can be easily documented or communicated.

Examples:

* Manuals
* Books
* Rules
* Tables
* Procedures
* Documents

## Tacit Knowledge

Knowledge that exists primarily through experience and is difficult to describe explicitly.

For example, an experienced mechanic may recognize a subtle engine sound and immediately suspect a particular problem.

The mechanic may know how to recognize the problem but may find it difficult to explain every part of the reasoning.

This is one reason knowledge elicitation can be challenging.

Knowledge can be acquired from several sources.

### Documents

Knowledge can be obtained from:

### Observations

### Existing Systems

# 4.4 Knowledge Engineer

A **knowledge engineer** plays an important role in expert system development.

The knowledge engineer acts as a bridge between the domain expert and the computer system.

```text
Domain Expert
      |
      v
Knowledge Engineer
      |
      v
Knowledge Representation
      |
      v

```

The domain expert understands the problem.

The knowledge engineer understands how to represent that knowledge in the computer system.

---

# 4.5 Problems in Knowledge Acquisition

Knowledge acquisition is often considered one of the most difficult parts of developing an expert system.

Common problems include:

### Knowledge Is Difficult to Express

Experts may know how to solve a problem without being able to clearly explain every step.

### Experts May Disagree

Two experts may use different approaches to solve the same problem.

### Tacit Knowledge

Important knowledge may be based on experience and intuition.

### Large Amount of Knowledge

Complex domains can contain thousands of facts and rules.

### Changing Knowledge

Knowledge may change over time.

### Communication Problems

The knowledge engineer and domain expert may use different terminology or have different technical backgrounds.

# 5. Knowledge Elicitation Techniques

## 5.1 What Is Knowledge Elicitation?

Knowledge elicitation is the process of obtaining knowledge from experts or other sources.

It is an important part of knowledge acquisition.

While knowledge acquisition is the broader process of collecting and incorporating knowledge, **knowledge elicitation focuses particularly on extracting knowledge from knowledgeable sources, especially human experts**.

---

# 5.2 Interviewing

Interviewing is one of the most common knowledge elicitation techniques.

The knowledge engineer asks questions to the domain expert.

There are two major approaches.

### Structured Interview

The questions are prepared in advance.

Example:

```text
Question 1:
What symptoms indicate this disease?

Question 2:
What tests are required?

Question 3:
What treatment should be considered?
```

### Unstructured Interview

The discussion is more flexible.

The expert can explain the problem freely and the knowledge engineer can ask follow-up questions.

---

# 5.3 Observation

The knowledge engineer observes the expert while the expert performs a real task.

For example, a knowledge engineer may observe a technician repairing a machine.

```text
Observe expert
      |
      v
Identify decisions
      |
      v
Identify reasoning
      |
      v
Convert observations into rules
```

Observation is especially useful when the expert has difficulty explaining tacit knowledge.

---

# 5.4 Questionnaires

Questionnaires allow experts to provide information through a structured set of questions.

They can be useful when:

* Multiple experts are involved
* Experts are geographically separated
* Large amounts of information must be collected

---

# 5.5 Think-Aloud Protocol

In the **think-aloud technique**, the expert is asked to describe their reasoning while solving a problem.

For example:

```text
Expert:

"The machine is making a clicking sound.
The power indicator is weak.
I would check the battery first."
```

The knowledge engineer analyzes the expert's reasoning to identify rules.

---

# 5.6 Protocol Analysis

Protocol analysis involves recording and analyzing an expert's problem-solving behavior.

The analysis may identify:

* Facts considered
* Decisions made
* Rules applied
* Alternatives rejected
* Sequences of reasoning

This technique is useful for complex decision-making tasks.

---

# 5.7 Case Analysis

Previous cases can be studied to identify patterns.

For example:

```text
Case 1:
Symptoms A + B -> Disease X

Case 2:
Symptoms A + C -> Disease Y

Case 3:
Symptoms B + C -> Disease X
```

Repeated patterns can help identify rules.

---

# 5.8 Document Analysis

Existing documents can be analyzed to discover knowledge.

Sources may include:

* Manuals
* Operating procedures
* Technical documentation
* Reports
* Research publications
* Policy documents

---

# 5.9 Brainstorming

A group of experts can work together to identify:

* Important concepts
* Possible rules
* Problems
* Solutions
* Relationships

Brainstorming can be useful during the early stages of knowledge development.

---

# 5.10 Knowledge Elicitation Summary

Different techniques are appropriate for different situations.

| Technique         | Main Purpose                             |
| ----------------- | ---------------------------------------- |
| Interview         | Ask experts directly                     |
| Observation       | Watch experts perform tasks              |
| Questionnaire     | Collect structured responses             |
| Think-Aloud       | Capture reasoning during problem solving |
| Protocol Analysis | Analyze problem-solving behavior         |
| Case Analysis     | Extract knowledge from historical cases  |
| Document Analysis | Extract documented knowledge             |
| Brainstorming     | Generate and organize domain knowledge   |

In practice, several techniques are often combined.

# 6. Forward Chaining vs Backward Chaining

Forward and backward chaining are two important inference techniques used in rule-based expert systems.

Both use rules, but they reason in different directions.

---

# 6.1 Rule Representation

Consider the following rules:

```text
Rule 1:
IF fever AND cough
THEN respiratory infection.

Rule 2:
IF respiratory infection
THEN medical examination required.
```

Suppose the system knows:

```text
Fact:
Fever = true

Fact:
Cough = true
```

The inference engine can reason from these facts to a conclusion.

This is forward chaining.

---

# 6.2 Forward Chaining

Forward chaining is a **data-driven reasoning technique**.

It starts with known facts and repeatedly applies rules to derive new facts until a goal is reached or no more rules can be applied.

The process is:

```text
Known Facts
    |
    v
Find Applicable Rules
    |
    v
Apply Rule
    |
    v
New Facts
    |
    v
Apply More Rules
    |
    v
Conclusion
```

---

# 6.3 Forward Chaining Example

Suppose we have:

```text
Fact:
Fever

Fact:
Cough
```

Rules:

```text
Rule 1:
IF fever AND cough
THEN infection.

Rule 2:
IF infection
THEN medical examination required.
```

Forward chaining proceeds like this:

```text
Fever + Cough
     |
     v
Rule 1
     |
     v
Infection
     |
     v
Rule 2
     |
     v
Medical examination required
```

The reasoning begins with available information.

---

# 6.4 Characteristics of Forward Chaining

Forward chaining:

* Starts with facts
* Moves toward conclusions
* Is data-driven
* Applies rules whose conditions are satisfied
* Can derive multiple conclusions
* Is useful when many new facts become available

It is particularly useful in systems where the input data is continuously changing.

---

# 6.5 Backward Chaining

Backward chaining is a **goal-driven reasoning technique**.

Instead of starting with all known facts, it starts with a goal or hypothesis and works backward to determine whether the available facts support that goal.

The process is:

```text
Goal
 |
 v
Find Rule That Produces Goal
 |
 v
Check Rule Conditions
 |
 v
Find Supporting Facts
 |
 v
Goal Confirmed or Rejected
```

---

# 6.6 Backward Chaining Example

Suppose the goal is:

```text
Goal:
Medical examination required
```

We have:

```text
Rule 2:
IF infection
THEN medical examination required.
```

Therefore, the system asks:

```text
Is infection true?
```

To determine this, it uses:

```text
Rule 1:
IF fever AND cough
THEN infection.
```

Then it checks:

```text
Is fever true?
Is cough true?
```

If both are true:

```text
Fever
 +
Cough
   |
   v
Infection
   |
   v
Medical examination required
```

The reasoning begins with the desired conclusion and moves backward toward the facts.

---

# 6.7 Forward vs Backward Chaining

| Feature             | Forward Chaining        | Backward Chaining              |
| ------------------- | ----------------------- | ------------------------------ |
| Reasoning direction | Facts to conclusion     | Goal to facts                  |
| Approach            | Data-driven             | Goal-driven                    |
| Starting point      | Known facts             | Goal or hypothesis             |
| Main question       | What can be concluded?  | Can this goal be proven?       |
| Useful when         | Lots of new data exists | A specific goal must be tested |
| Reasoning style     | Bottom-up               | Top-down                       |
| Common use          | Monitoring and control  | Diagnosis and query answering  |

---

# 6.8 Simple Comparison

Forward chaining:

```text
Facts
 ↓
Rules
 ↓
New Facts
 ↓
Conclusion
```

Backward chaining:

```text
Goal
 ↓
Rules
 ↓
Required Conditions
 ↓
Facts
```

A simple way to remember them is:

```text
Forward = Start from what you KNOW.

Backward = Start from what you WANT TO PROVE.
```

---

# 6.9 Example From Medical Diagnosis

Suppose:

```text
Facts:
Fever
Cough
Fatigue
```

Rules:

```text
IF fever AND cough
THEN infection.

IF infection AND fatigue
THEN possible flu.
```

### Forward Chaining

```text
Fever + Cough
      |
      v
Infection
      |
      v
Infection + Fatigue
      |
      v
Possible Flu
```

### Backward Chaining

Start with:

```text
Goal:
Possible Flu
```

Then determine:

```text
Need:
Infection + Fatigue
```

Then determine:

```text
Need:
Fever + Cough
```

Finally verify the facts.

# 7. Development of an Expert System

Developing an expert system is a systematic process that converts domain knowledge into a working software system.

A simplified development process is:

```text
Problem Identification
        |
        v
Feasibility Study
        |
        v
Knowledge Acquisition
        |
        v
Knowledge Representation
        |
        v
Inference Design
        |
        v
Prototype Development
        |
        v
Testing and Validation
        |
        v
Deployment
        |
        v
Maintenance
```

---

# 7.1 Step 1: Problem Identification

The first step is to clearly define the problem.

A good expert-system problem generally has:

* A specific domain
* Clear goals
* Available expert knowledge
* A need for reasoning or decision support

Example:

```text
Problem:
Diagnose common computer hardware failures.
```

---

# 7.2 Step 2: Feasibility Study

Before development begins, determine whether an expert system is appropriate.

Important questions include:

```text
Is expert knowledge available?

Can the knowledge be represented?

Is the problem suitable for rule-based reasoning?

Will the system provide useful results?

Can the system be maintained?
```

A feasibility study reduces the risk of developing an impractical system.

---

# 7.3 Step 3: Knowledge Acquisition

Knowledge is collected from experts and other sources.

For example:

```text
Experts
Documents
Manuals
Historical Cases
Databases
```

The collected information is analyzed and organized.

---

# 7.4 Step 4: Knowledge Representation

The collected knowledge must be represented so that the computer can use it.

Common representation methods include:

### Rules

```text
IF condition
THEN conclusion
```

Example:

```text
IF computer does not power on
AND power cable is connected
THEN check power supply.
```

### Facts

```text
Power cable is connected.
```

### Semantic Networks

Knowledge can be represented as a network of concepts and relationships.

```text
Animal
  |
  +-- Mammal
        |
        +-- Dog
```

### Frames

Frames organize knowledge around objects or concepts.

Example:

```text
Employee
  |
  +-- Name
  +-- Department
  +-- Position
  +-- Salary
```

```text

       |
```

When differences occur, the underlying rules should be examined.

# 9. Difference Between Expert Systems and Machine Learning

Although both are AI techniques, they have important differences.

| Feature                  | Expert System                      | Machine Learning                    |
| ------------------------ | ---------------------------------- | ----------------------------------- |
| Knowledge source         | Experts and documented knowledge   | Data and examples                   |
| Main mechanism           | Rules and inference                | Learning algorithms                 |
| Knowledge representation | Explicit rules/facts               | Learned model                       |
| Explanation              | Often easier in rule-based systems | Can be difficult depending on model |
| Data requirement         | May work with limited data         | Often requires substantial data     |
| Updating                 | Knowledge base is updated          | Model may need retraining           |
| Typical use              | Decision support and diagnosis     | Prediction and pattern recognition  |

For example:

```text
Expert System:

IF fever AND cough
THEN possible infection
```

Machine learning:

```text
Thousands of historical patient records
           |
           v
      ML Algorithm
           |
           v
       Trained Model
           |
           v
      New Prediction
```

Modern AI applications can combine both approaches.

# 11. Important Terms to Remember

For examination purposes, the following definitions are useful.

### Expert System

An AI system that uses domain knowledge and inference techniques to solve specialized problems.

### Knowledge Base

The component that stores facts, rules, and domain-specific knowledge.

### Inference Engine

The component that applies reasoning rules to derive conclusions.

### Knowledge Acquisition

The process of collecting and incorporating knowledge into an expert system.

### Knowledge Elicitation

The process of obtaining knowledge from experts or other knowledge sources.

### Forward Chaining

A data-driven inference method that starts from known facts and derives conclusions.

### Backward Chaining

A goal-driven inference method that starts from a goal and works backward to supporting facts.

### Knowledge Engineer

A person who collects, organizes, represents, and maintains expert knowledge for an AI system.

# Conclusion

Learning in machines and expert systems are important areas of Artificial Intelligence that demonstrate two different ways of building intelligent behavior.

Machine learning allows computers to discover patterns from data, while traditional expert systems represent human expertise explicitly through facts, rules, and reasoning mechanisms.

The architecture of an expert system typically includes a **knowledge base, inference engine, working memory, user interface, explanation facility, and knowledge acquisition facility**.

Knowledge itself can take different forms, including **declarative, procedural, heuristic, meta, structural, and common-sense knowledge**.

Building the knowledge base requires **knowledge acquisition**, while techniques such as interviews, observation, questionnaires, think-aloud protocols, case analysis, and document analysis can be used for **knowledge elicitation**.

For reasoning, two major techniques are **forward chaining** and **backward chaining**:

```text
Forward Chaining
Facts → Rules → Conclusions

Backward Chaining
Goals → Rules → Supporting Facts
```

Finally, an expert system is developed through a systematic process that includes **problem identification, feasibility analysis, knowledge acquisition, knowledge representation, inference design, prototyping, testing, validation, deployment, and maintenance**.

Understanding these concepts provides a strong foundation for studying Artificial Intelligence, knowledge-based systems, machine learning, and intelligent decision-support applications.
